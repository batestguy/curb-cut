# Alt-text that can't lie

*Draft for the author's edit, 2026-11-08. Numbers are from the live site's chart data and the library's documentation; check them again after any edit.*

A screen-reader user can't see a chart. They hear its text alternative, the "alt-text", and trust it. If it says "Taraba has the highest disability rate in Nigeria", they have no way to check. Sighted readers at least see the error bars.

Most chart alt-text is either empty ("chart"), or written by hand once and never updated, or now generated by AI. All three can state things the data does not support. So for [Curb Cut](https://batestguy.github.io/curb-cut/) I built a chart library whose descriptions are checked against the data before they are published: [`disability-access-charts`](https://pypi.org/project/disability-access-charts/).

## How it works

1. **Descriptions are written from the data.** `dot()`, `bar()` and `choropleth()` return one document per chart: the Plotly spec, a description, a data table and an audit. The description is built from templates filled with the chart's own numbers, so it cannot drift from them.
2. **A claim checker tests every sentence.** It finds each number and each comparison it recognises ("higher than", "the highest", "twice", "ranked 3rd") and tests it against the data.
3. **Comparisons are tested against the confidence intervals,** not the point estimates. "A is higher than B" passes only if |a − b| > 1.96 · √(se_a² + se_b²), a two-sided z-test at the 5% level, with each standard error taken from its interval.
4. **The audit runs in CI.** Every chart on the site is checked with `disability-access-charts check --strict` before the site is built; one failing chart stops the build.

## A real example

In the Nigeria DHS 2024, Taraba's estimate (11.3% of adults) is the highest of the 37 states and Abia's (10.6%) the second. "Taraba is higher than Abia" sounds true. The checker rejects it: the difference is 0.70 points, and the intervals require more than 3.74 to show one. It suggests the wording "the survey cannot show a difference", and that is what the site says.

For the chart's own summary, the library goes further. It counts every comparison it makes and controls the false discovery rate (Benjamini–Hochberg at 5%). The state chart checks 73 comparisons, and only 20 hold up. Those 20 are the only comparisons the description states.

## What it doesn't do

- **It checks truth, not usefulness.** Whether a description is clear or helpful is for people, not code, to judge. The site has not yet been tested by a regular screen-reader user.
- **It knows a vocabulary.** Claims it doesn't recognise (causes, trends, "3 points higher") are not checked, and some are only warned about. How often it misses a false claim has not yet been measured.
- **The test is approximate.** It assumes roughly normal, independent estimates, and it does not correct for multiple comparisons; the findings summary does.

Other tools solve a different problem. [maidr](https://pypi.org/project/maidr/) and [Olli](https://mitvis.github.io/olli/) make charts explorable by keyboard, sound or braille. This library checks what a description claims. They work well together.

## Try it

```bash
pip install "disability-access-charts[plotly]"
```

The [README](https://github.com/batestguy/curb-cut#the-chart-library-in-ten-steps) walks through ten steps, from install to a rejected claim. The library is MIT-licensed and has no dependencies beyond the optional Plotly. Descriptions are also drafted in Hausa, Yorùbá, Igbo and Pidgin; those were written by an AI model and still need a native speaker's review, and each is checked by its own language's claim checker.

If you publish charts, try running the checker on your own alt-text. I'd like to hear what it catches, and what it misses.
